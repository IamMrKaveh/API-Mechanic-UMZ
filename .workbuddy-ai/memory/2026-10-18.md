# ۲۰۲۶-۱۰-۱۸ — ممیزی امنیتی کامل پروژه

- گزارش فازبندی‌شده در `SECURITY-AUDIT-REPORT.md` نوشته شد: ۲۶ یافته (۳ بحرانی، ۸ مهم، ۹ متوسط، ۶ کم/اطلاعاتی) با راه‌حل تمیز برای هرکدام + نقشه راه ۳ هفته‌ای + فهرست نقاط قوت موجود (باید حفظ شوند).
- مهم‌ترین یافته‌ها:
  - SEC-01 بحرانی: رازهای production در Git — `otp.json` (لاگ AI ۳MB شامل appsettings.Production.json با رمز زندهٔ Supabase) + کلید JWT/Kavenegar/S3 در `appsettings.json`. راه‌حل: rotate + git filter-repo + gitleaks (pre-commit/CI).
  - SEC-02 بحرانی: `WalletController` mark-paid/reject فقط `[Authorize]` کلاسی (بدون نقش) → هر کاربر می‌تواند برداشت دیگران را علامت/رد کند (هندلرها admin check ندارند).
  - SEC-03 مهم: IDOR روی `UserController` GET/PUT /users/{id} (هندلرها ICurrentUserService ندارند).
  - SEC-05 مهم: `SecurityMiddleware` لیست سفید IP ادمین پیشوند `/api/admin` را می‌کند ولی مسیرها `api/v{version}/admin/...` هستند → عملاً غیرفعال + fail-open.
  - SEC-06 مهم: وب‌هوک پرداخت بدون احراز هویت (فلگ‌های signature/IP پیش‌فرض false + fail-open در WebhookIpWhitelistMiddleware).
  - SEC-07/08/09 مهم: ری‌فرش‌توکن plaintext، OTP unsalted SHA-256، lockout تنظیم‌شده ولی bind/مصرف‌نشده.
  - SEC-11 متوسط: ResolveFrontendBaseUrl هدر Origin را بدون allow-list می‌پذیرد → open redirect در کالبک کیف پول.
- نکات مثبت تأییدشده (حفظ شود): BCrypt wf=12، OTP با CSPRNG + هش، کوکی __Host-refresh امن، HSTS/CSP کامل، SQL کاملاً پارامتری، تأیید مبلغ پیش از اعمال پرداخت، JWT validation سختگیرانه (HS256 pinned، ClockSkew 30s)، AES-GCM در کش Redis، لاگ بدون بدنه/هدر حساس.
- هیچ تغییری در کد اعمال نشد (گزارش تحلیلی). کاربر باید mount تصمیم rotate/اجازه اصلاحات را بدهد.
